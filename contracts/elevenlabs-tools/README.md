# ElevenLabs Tool Definitions

Copy-paste-ready webhook tool configs for the ElevenLabs Conversational AI agent.
These are the **corrected, flat-body** definitions (a nested body or a missing
URL path is the #1 cause of tools silently failing).

## Files
| File | Endpoint | Purpose |
|------|----------|---------|
| `lookup_sku.json` | `POST /webhook/sku-lookup` | Catalog / price / stock lookup |
| `check_availability.json` | `POST /webhook/calendar-check` | Open appointment slots for a date |
| `book_appointment.json` | `POST /webhook/calendar-book` | Create a calendar booking |
| `post_call_summary_logger.json` | `POST /webhook/call-summary-logger` | Persist call log to Supabase |

## Before pasting, replace the two placeholders
- `{{NGROK_OR_DOMAIN}}` → your public host, e.g. `abc123.ngrok-free.dev` or `n8n.yourcompany.com`
- `{{WEBHOOK_SECRET}}` → the value of `WEBHOOK_SECRET` in your `.env` (or your ElevenLabs shared secret)

## Rules that keep tools working
1. **URL must include the `/webhook/<name>` path** — pointing at the bare domain yields `Cannot POST /`.
2. **Request body must be flat** — do not wrap fields in an object (e.g. `date_and_timezone`, `customer_info`). The n8n workflows also tolerate one level of nesting as a safety net, but flat is the contract.
3. **`X-Webhook-Secret` must match** `WEBHOOK_SECRET` exactly (no surrounding quotes).

## Recommendation for the logger
Wire `post_call_summary_logger` as the ElevenLabs **post-call webhook**
(Agent → Settings → Webhooks) rather than an LLM tool, so the real transcript and
metadata are delivered automatically instead of being generated by the model.
